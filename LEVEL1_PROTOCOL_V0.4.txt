===============================================================================
1. PURPOSE
===============================================================================

Level 1 tests a deterministic compressor across five distinct valid inputs
under the frozen restricted-language software pipeline.

The pipeline is:

INPUT_i
→ DETERMINISTIC COMPRESSOR
→ CANDIDATE_i
→ FROZEN LEVEL 0 EXTRACTOR V0.4
→ FROZEN LEVEL 0 COMPARATOR V0.4
→ VERDICT_i

Level 1 asks whether the frozen compressor:

1. reads each input rather than returning a fixture-specific constant;
2. produces a shorter representation;
3. preserves the facts of that specific input;
4. remains deterministic across repeated execution;
5. fails closed on an invalid input.

Level 1 is:

RESTRICTED_LANGUAGE_PIPELINE_VALIDATION

Level 1 is NOT:

MEMORY_MODEL_PROOF
GENERAL_MEMORY_VALIDATION
GENERAL_NATURAL_LANGUAGE_COMPRESSION
GENERAL_SEMANTIC_PRESERVATION_PROOF
PHYSICAL_VALIDATION
AGI_VALIDATION
ASI_VALIDATION
GENERAL_THEOREM

5. GRAMMAR DEPENDENCY RULE
===============================================================================

The compressor MAY read and interpret the frozen REV3 grammar JSON.

The compressor MAY implement its own parser from the frozen grammar.

The compressor MAY import:

level0_extract_v0_4.py

only if that dependency is declared before compressor freeze.

The compressor MUST NOT import:

level0_compare_v0_4.py

The compressor MUST NOT read V or Q directly or indirectly.

If the compressor imports `level0_extract_v0_4.py`, the Level 1 record MUST
state:

SHARED_PARSER_LIMITATION = ACTIVE

Meaning:

The compressor and evaluator share the same parser implementation.

Therefore a Level 1 pass in that configuration demonstrates pipeline
consistency under a shared parser and does NOT constitute an independent
cross-check of parsing correctness.

===============================================================================
14. ANTI-CONSTANT CHECK
===============================================================================

For each held-out control input:

i ∈ {2, 3, 4, 5}

the corresponding V_i must first satisfy:

V_i != ORIGINAL_V

at the semantic fact-set level.

Otherwise:

PROTOCOL_ERROR

The same OUTPUT_i is then also compared against the ORIGINAL frozen V.

Required result:

OUTPUT_i AGAINST ORIGINAL_V
MUST NOT
RETURN TWIN_VALID

Therefore:

ANTI_CONSTANT_CHECK_i = PASS

iff:

TRIAL_VERDICT != TWIN_VALID

This prevents a compressor that ignores its input and always emits a valid
rendering of original M_0 from passing Level 1.

For L1_R01, no anti-constant check is required because V_1 is original V.

===============================================================================
15. LENGTH RULE — PER INPUT
===============================================================================

The length threshold is computed independently for each input.

For valid input i:

RATIO_i
=
OUTPUT_LENGTH_i / INPUT_LENGTH_i

Required:

RATIO_i < 0.70

Therefore:

LENGTH_PASS_i
iff
OUTPUT_LENGTH_i / INPUT_LENGTH_i < 0.70

The original M_0 has:

INPUT_LENGTH_1 = 789

Therefore for L1_R01 only:

MAXIMUM_PASSING_OUTPUT_LENGTH = 552 characters

For control inputs:

552 IS NOT A UNIVERSAL LIMIT.

Each control uses its own input length.

===============================================================================
16. CHARACTER-COUNTING RULE
===============================================================================

For both input and output:

1. decode as UTF-8;
2. reject BOM;
3. normalize to Unicode NFC;
4. remove nothing from the semantic text;
5. if and only if the stored file has exactly one final LF used solely as
   file termination, exclude that one final LF from the semantic count;
6. do not alter any other whitespace;
7. do not rewrite punctuation;
8. do not rewrite aliases;
9. count Unicode code points in the resulting text.

Zero bytes are not removed.

If a zero byte is present:

INPUT_OR_OUTPUT_ENCODING_FAIL

18. RAW OUTPUT TRANSFER AND HASHING
===============================================================================

If an output is transferred through chat or another interface, the candidate is
defined as the exact text contained in one declared candidate block.

The operator reconstructs the candidate exactly as received.

RAW_OUTPUT_SHA256 is computed by code at receipt.

The model or compressor is not treated as the authority for the received hash.

The operator records:

received byte length
received SHA-256
semantic character length

If transfer corruption is detected before scoring:

TRANSFER_FAILURE

The run remains recorded and may not be silently replaced.

19. DETERMINISM REQUIREMENT
===============================================================================

Every valid input is executed twice.

For each input i:

OUTPUT_i_A
OUTPUT_i_B

must be byte-identical.

Required:

SHA256(OUTPUT_i_A)
=
SHA256(OUTPUT_i_B)

If not:

DETERMINISM_FAIL_i

and that input fails Level 1.

The duplicate execution is a determinism check.

It is NOT counted as a sixth, seventh, eighth, ninth, or tenth experimental
input.

Thus:

PRIMARY_INPUT_COUNT = 5
EXECUTION_COUNT_FOR_VALID_INPUTS = 10
